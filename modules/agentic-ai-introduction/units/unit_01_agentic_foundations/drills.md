## 2. Part 1: Foundational Concept Checks
Formulate your answer first, then click the bar to verify your reasoning against the architectural rationale.

<details>
<summary>Question 1: What is the primary operational distinction between a "Workflow" and an "Agent" under Anthropic's taxonomy?</summary>

**Architectural Rationale:**
- **Workflows** are systems where LLMs and tools are orchestrated through **predefined, hardcoded code paths** (e.g., Python `if/else`, linear pipelines, or static DAGs). The control flow is deterministic and decided by human software engineers.
- **Agents**, by contrast, are systems where the **LLM dynamically directs its own process and tool usage**, maintaining control over how many steps to take, which tools to invoke, and when the task is complete based on runtime environment feedback.
- *Rule of Thumb*: If the sequence of steps can be drawn on a whiteboard as a fixed flowchart, build a **Workflow**. If the sequence of steps depends entirely on what the model discovers at runtime, build an **Agent**.
</details>

<details>
<summary>Question 2: In the ReAct framework (Yao et al., 2023), why does combining Thought and Action outperform pure Chain-of-Thought (CoT)?</summary>

**Architectural Rationale:**
- In pure **Chain-of-Thought (CoT)**, the model only reasons internally using frozen parametric weights. On factual or multi-step API tasks, any early hallucination compounds down the reasoning chain without any mechanism to catch or correct it.
- In **ReAct (Reasoning + Acting)**, the model outputs a verbal **Thought** to plan its next step, selects an external **Action** (tool call), and receives an **Observation** from the external environment.
- The observation provides **ground-truth feedback** that grounds the next thought, allowing the model to dynamically update its knowledge, discover unexpected errors, and adjust its plan rather than hallucinating.
</details>

<details>
<summary>Question 3: When should a system architect choose the "Routing" workflow over loading all tools into a single agent prompt?</summary>

**Architectural Rationale:**
- **Context Pollution & Distraction**: Dumping 50 tool schemas into a single prompt degrades model reasoning, increases latency, and drastically raises the probability of tool hallucinations or selecting the wrong tool.
- **Cost & Latency Optimization**: Routing classifies the user's intent first, allowing the system to dispatch the request to a focused sub-prompt equipped with *only* the 2–3 tools required for that domain.
- **Model Tiering**: A router can send simple FAQ queries to small, fast models (e.g., Claude 3.5 Haiku) and route complex reasoning tasks to frontier models (e.g., Claude 3.5 Sonnet).
</details>

<details>
<summary>Question 4: What is the "Poka-Yoke" principle in Agent-Computer Interface (ACI) design, and why are relative filepaths dangerous?</summary>

**Architectural Rationale:**
- **Poka-Yoke** means mistake-proofing tools so the model cannot easily produce invalid inputs.
- When an agent executes shell commands or edits files across multiple turns, it frequently changes working directories (`cd /sub/dir`). If a file-reading tool accepts relative paths (e.g. `../config.json`), the model loses track of its current working directory and reads the wrong file or fails.
- By enforcing **absolute paths** (`/workspace/project/config.json`) in the tool schema, the ACI becomes immune to working-directory drift.
</details>

## 3. Part 2: ReAct State Traces & Architectural Scenarios

### Trace Drill 1: Deconstructing a ReAct State Machine
Examine the following pseudo-log generated by an autonomous research agent:

```text
Turn 1:
Thought: I need to find the latest quarterly earnings for Acme Corp. I will query the SEC filings tool.
Action: QueryFilings{"ticker": "ACME", "form": "10-Q", "year": 2026}
Observation: Error: Form 10-Q for 2026 not found. Most recent filing is 2025 Q4 (Form 10-K).

Turn 2:
Thought: The 2026 10-Q is not yet filed. The most recent annual report is 2025 10-K. I will query the 2025 10-K for annual revenue instead.
Action: QueryFilings{"ticker": "ACME", "form": "10-K", "year": 2025}
Observation: Annual Revenue: $4.2B, Net Income: $320M.

Turn 3:
Thought: I have retrieved the confirmed 2025 financial figures. I can now synthesize the response for the user.
Action: Finish{"answer": "Acme Corp has not yet filed a 2026 10-Q. According to their 2025 Form 10-K, annual revenue was $4.2B with net income of $320M."}
```

<details>
<summary>Trace Analysis: What would happen if this system had been implemented as a linear sequential pipeline (without the ReAct feedback loop)?</summary>

**Architectural Analysis:**
1. In a rigid **Sequential Pipeline** (`Query 2026 10-Q` $\to$ `Format Report`), the failure in Turn 1 (`Form 10-Q not found`) would either crash the pipeline with an unhandled exception or cause the formatting step to generate a hallucinated or empty response.
2. In the **ReAct loop**, the error message returned as an `Observation` served as environmental ground truth.
3. The model's `Thought` in Turn 2 analyzed the observation, realized 2026 data did not exist, and autonomously adapted its plan to fall back to the 2025 10-K.
</details>

### Trace Drill 2: Selecting the Optimal Workflow Pattern
A company needs to implement four distinct AI capabilities. Match each business problem with the optimal pattern from Anthropic's architecture:

- **Scenario A**: An e-commerce system receives user queries. 70% are simple order-status lookups, 20% are complex return disputes, and 10% are product recommendations.
- **Scenario B**: A legal AI drafts employment contracts. First it generates the core terms, checks that mandatory state compliance clauses exist, and then writes the full legal clauses.
- **Scenario C**: A code review bot runs 5 independent security checks simultaneously (SQL injection, XSS, hardcoded secrets, dependency vulnerabilities, and license compliance) across a pull request.
- **Scenario D**: An automated marketing writer creates ad copy. A separate compliance critic reviews the ad for FTC truth-in-advertising guidelines and sends specific feedback back to the writer until it passes.

<details>
<summary>Click to verify pattern matching</summary>

**Pattern Mapping:**
- **Scenario A $\to$ Routing**: Classify the user query at the front door. Route order lookups to a lightweight model with a database tool; route return disputes to a specialized policy prompt.
- **Scenario B $\to$ Prompt Chaining (with Gates)**: Linear sequence of steps where an intermediate programmatic code gate verifies that state compliance clauses exist before the final drafting step executes.
- **Scenario C $\to$ Parallelization (Sectioning)**: Split the code audit into 5 independent subtasks executed concurrently for low latency.
- **Scenario D $\to$ Evaluator-Optimizer (Critique Loop)**: Generator LLM (Writer) + Evaluator LLM (Compliance Critic) iterating until the rubric criteria are satisfied.
</details>

### Trace Drill 3: Debugging an Infinite ReAct Runaway Loop
Examine the following failing agent trace:

```python
# Unsafe Agent Harness
def run_agent(goal):
    messages = [{"role": "user", "content": goal}]
    while True:
        response = llm.generate(messages)
        if response.has_tool_call:
            result = execute_tool(response.tool_call)
            messages.append({"role": "assistant", "content": response.text})
            messages.append({"role": "user", "content": f"Observation: {result}"})
        else:
            return response.text
```

<details>
<summary>Click to identify the 3 critical failure modes in this loop harness and their solutions</summary>

**Failure Modes & Mitigations:**
1. **Unbounded `while True` (No Max Iterations)**: If the LLM enters an unrecoverable tool error or repeats the same failed query, the loop runs forever, exhausting API rate limits and burning hundreds of dollars.
   - *Fix*: Enforce `for iteration in range(max_iterations):` (e.g. `max_iterations=5`). If the loop terminates without reaching a `Finish` action, raise an explicit `AgentMaxIterationsExceededError`.
2. **Context Window Explosion**: Appending full raw observations on every turn without truncation will exceed model context windows (or blow token budgets) on large outputs.
   - *Fix*: Truncate tool observations to a reasonable length (e.g., 2,000 characters) and summarize or paginate data.
3. **Repeated Action Thrashing**: The harness does not check if the model is calling the exact same failing tool with identical arguments.
   - *Fix*: Track a call history set `seen_calls.add((tool_name, json_args))`. If a duplicate call is attempted, inject an explicit warning: `Observation: Error - You have already executed this exact call. Please try an alternative approach.`
</details>
