  The Problem Statement

A raw pre-trained base model is an unguided autocomplete engine: if prompted with 'What is the capital of France?', it might simply continue with 'What is the capital of Germany?'. Supervised Fine-Tuning (SFT) transforms base models into conversational, instruction-following assistants. However, full-parameter fine-tuning of multi-billion parameter models requires prohibitive GPU compute and storage. Parameter-Efficient Fine-Tuning (PEFT), particularly LoRA and QLoRA, solves this barrier by freezing base model weights and training lightweight adapter matrices, democratizing model customization.

  Theoretical Framework

The Fine-Tuning Spectrum:

  • Continued Pre-Training: Unsupervised training on domain text (legal, medical) using standard next-token prediction to instill vocabulary and background knowledge.
  • Supervised Fine-Tuning (SFT): Training on paired instruction-response examples to teach turn-taking format, tone, and structured output adherence.
  • Parameter-Efficient Fine-Tuning (LoRA): Based on the hypothesis that weight updates during adaptation have a low intrinsic dimension. LoRA freezes original weights W_0 (d x k) and injects trainable low-rank matrices B (d x r) and A (r x k), where rank r << min(d, k):
h = W_0 * x + (alpha / r) * (B * A) * x

Only matrices A and B receive gradient updates during training, reducing trainable parameters and optimizer memory by 99%.

QLoRA Innovations: Quantizes the frozen base model to 4-bit NormalFloat (NF4), applies double quantization to compress quantization constants, and utilizes paged optimizers to manage memory spikes, allowing fine-tuning of 70B models on a single consumer GPU.

Catastrophic Forgetting: Occurs when gradient updates on a narrow dataset overwrite neural circuits responsible for general reasoning and commonsense. Mitigated by mixing general instruction data into the domain dataset (co-training).

  Implementation Guide

Production workflow for fine-tuning instruction models:

  1. Format Instruction Datasets: Structure training data into conversational roles (system, user, assistant) and apply the model's exact Chat Template (e.g., Llama-3, ChatML) with special delimiter tokens.
  2. Apply Loss Masking: Calculate cross-entropy loss exclusively on the assistant's response tokens, masking out user prompt tokens so the model is not penalized for user phrasing.
  3. Configure LoRA Hyperparameters: Target all linear projection layers (q_proj, k_proj, v_proj, o_proj, gate_proj, up_proj, down_proj). Set rank r=16 or 32, alpha=2*r, and learning rate ~2e-4.
  4. Evaluate with Benchmarks: Monitor validation loss and evaluate on both domain-specific test sets and general reasoning benchmarks (MMLU, GSM8K) to ensure general capability retention.
