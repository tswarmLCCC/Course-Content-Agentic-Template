## 1. Executive Summary & Pedagogical Context

Over the past two years, the software engineering world has witnessed the rapid collapse of syntax friction. Today, over 40% of all newly committed code is generated by AI models. However, this ease of generation has given rise to a dangerous development anti-pattern: **"Vibe Coding"**—the habit of typing casual, unstructured natural language prompts into a chat box, copying whatever code is emitted, and repeatedly pasting back error tracebacks when execution inevitably crashes.

While vibe coding feels magical for toy weekend scripts, it fails catastrophically in enterprise production. It creates a deceptively low upfront capital expense (**CapEx**) paired with astronomical long-term operational maintenance costs (**OpEx**), context pollution, and the dreaded **"80% Trap"**—where an agent rapidly generates 80% of an application in 15 minutes, but the human engineer spends two weeks trapped trying to resolve mysterious regressions, edge cases, and architectural drift.

As articulated in Google's landmark whitepaper (*The New SDLC With Vibe Coding* by Addy Osmani, Shubham Saboo, and Sokratis Kartakis), the industry is pivoting toward **Agentic Engineering**. 

The cornerstone of this discipline is **The 10/90 Harness Rule**:
$$\text{Agent System Success} = \text{Model (10\%)} + \text{Harness (90\%)}$$

The underlying AI model provides the raw reasoning core, but accounts for only 10% of real-world reliability. The remaining **90% is the execution harness**—the repository rules (`AGENTS.md`), machine-actionable specifications (EARS syntax), non-destructive diff patchers, AST linters, and closed test verification loops that govern what the agent can and cannot touch.

## 3. Measurable Learning Objectives

By the end of this unit, you will be able to:
1. **Differentiate** unstructured vibe coding from disciplined agentic engineering using Google's 10/90 Harness Principle.
2. **Deconstruct** the economic and architectural causes of the "80% Trap" (compounding error rates, context pollution, and lack of deterministic boundary conditions).
3. **Formulate** machine-actionable specifications using Easy Approach to Requirements Syntax (**EARS**) across Ubiquitous, Event, State, and Unwanted behavior types.
4. **Contrast** the operational responsibilities of the modern software developer as an interactive **Conductor** versus an asynchronous **Orchestrator**.
5. **Implement** an automated Python agent harness that ingests an EARS specification, generates targeted implementation code, runs isolated unit tests, and iteratively self-corrects defects until all assertions pass.
