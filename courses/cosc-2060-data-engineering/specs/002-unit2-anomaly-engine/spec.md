## 1. Objective & Target Audience
- **Primary Persona**: College Sophomores (2nd-year undergraduates) with introductory SQL and intro ML experience.
- **The Cognitive Gap**: In ML class, students used Pandas on small datasets (< 100,000 rows) with `.apply()` and `get_dummies()`. When scaled to 1,000,000+ records, Pandas crashes with Out-Of-Memory (OOM) errors and locks up single-threaded CPU cores. Furthermore, students are accustomed to supervised labels; they struggle to understand how distance distortion in unnormalized features sabotages unsupervised anomaly detection.
- **Pedagogical Stance & Scaffolding**: 
  - Carefully scaffolded ("I Do, We Do, You Do") transitioning from imperative Pandas loops to declarative Polars expressions (`pl.col()`).
  - Intermediate ASCII/Markdown schemas showing data state before and after imputation, normalization, and encoding.
  - 80% Data Engineering / 20% ML focus: Emphasize memory-efficient tabular transformations, using Scikit-Learn's `IsolationForest` as the downstream evaluation consumer.
- **One Job**: Ingest 1,000,000 raw fuel transaction records, clean missing values, programmatically normalize numerical features and encode categorical variables using Polars LazyFrames, and output a standardized feature matrix evaluated by an Isolation Forest anomaly detector.

## 2. Requirements (EARS Syntax)

### Deliverable A: Master Reading & Conceptual Lecture Guide
- **Always (Ubiquitous)**:
  - `REQ-01`: The reading guide **shall** contain the 6 core pedagogical sections: Unit Overview & Bloom's Objectives, Narrative of Real-World Friction, Conceptual Metaphor, Technical Deep Dive, Guided Hands-on Practice, and FAQs/Gotchas with exact quoted error messages.
  - `REQ-02`: The reading guide **shall** deconstruct why unnormalized features distort distance-based and density-based anomaly algorithms (e.g. an unscaled `odometer` in thousands dominating a scaled `gallons_pumped` in tens).
  - `REQ-03`: The reading guide **shall** contrast Pandas' single-threaded Python object model against Polars' Apache Arrow columnar memory architecture, multi-threading in Rust, and Lazy vs. Eager execution models.
- **When (Event-Driven)**:
  - `REQ-04`: **When** presenting Polars syntax, the text **shall** illustrate the declarative expression context (`select`, `with_columns`, `filter`, `group_by`) versus imperative Pandas loops.
  - `REQ-05`: **When** introducing LazyFrames, the text **shall** demonstrate how `.lazy()` builds an optimized query plan before `.collect()` streams and computes results.
- **While (State-Driven)**:
  - `REQ-06`: **While** demonstrating intermediate transformation states, the reading **shall** include step-by-step ASCII/Markdown tables (`REQ-14`) tracing rows through raw input, null imputation, Z-score/Min-Max scaling, and one-hot encoding.
- **If-Then (Error & Defensive Mitigation)**:
  - `REQ-07`: **If** a Polars expression fails due to schema mismatches, type promotion issues, or calling eager methods on a LazyFrame, **then** the FAQ section **shall** quote the exact `polars.exceptions.ComputeError` or `SchemaError` and provide concrete fixes.

---

### Deliverable B: Applied Lab 2 Package & Starter Script
- **Always (Ubiquitous)**:
  - `REQ-08`: The lab guide **shall** follow the 3-part layout from `docs/unit_lab_guide.html`:
    1. Lecture Walkthrough & Coding Clinic ("I Do, We Do, You Do" on Polars expressions).
    2. Applied Lab Challenges (100 Points across 3 progressive parts) with copy-and-paste `lab2_starter.py`.
    3. Comprehensive 100-Point Evaluation Rubric.
  - `REQ-09`: The lab pipeline **shall** process 1,000,000 raw fuel records generated by `generate_fuel_data.py`.
- **When (Event-Driven)**:
  - `REQ-10`: **When** cleaning data, students **shall** programmatically impute missing values (median for continuous metrics, explicit `'UNKNOWN'` for categoricals) using Polars expressions without converting to Pandas.
  - `REQ-11`: **When** normalizing continuous features (`gallons_pumped`, `unit_price`, `transaction_amount`, `odometer_reading`), students **shall** implement Min-Max or Standard scaling natively in Polars expressions.
- **If-Then (Defensive Anomaly Detection Check)**:
  - `REQ-12`: **If** known embedded fraud patterns exist (tank capacity overfills > 300 gallons, impossible GPS speed between swipes, midnight dormant card activity), **then** the downstream Isolation Forest **shall** flag these transactions with negative anomaly scores ($< 0$).

---

### Deliverable C: Synthetic Fuel Data Generator (`generate_fuel_data.py`)
- **Always (Ubiquitous)**:
  - `REQ-13`: The script **shall** execute locally via Python and generate exactly 1,000,000 records saved to `data/fuel_transactions.parquet` in under 15 seconds.
  - `REQ-14`: The generator **shall** embed deterministic fraud anomalies (at a ~1% contamination rate):
    - Fuel volume exceeding maximum semi-truck tank capacity (> 300 gallons).
    - Impossible velocity (> 200 mph calculated between consecutive card swipes for the same driver).
    - Dormant card usage (transactions between 1:00 AM and 4:00 AM on inactive/retired driver IDs).

---

### Deliverable D: Companion Reference Module
- **Always (Ubiquitous)**:
  - `REQ-15`: The reference guide **shall** benchmark memory consumption (RSS in MB/GB), execution wall-clock time, and CPU thread utilization between Pandas 2.x and Polars on the identical 1M row fuel dataset.

---

## 3. Deliberately Out of Scope
- Web APIs (FastAPI) are **strictly out of scope** for Unit 2; deferred to Unit 5.
- Deep hyperparameter grid search (optimizing `n_estimators`, `max_samples`, `contamination`) is out of scope; focus is 80% on the data engineering pipeline.
- Distributed cluster computing (PySpark, Ray) is out of scope; all work is local-first using Polars multi-threading.
