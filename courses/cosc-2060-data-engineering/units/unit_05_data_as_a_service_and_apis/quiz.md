## Answer Key
| Question # | Correct Answer | Concept Tested & Rationale |
| :--- | :--- | :--- |
| **1** | **B** | FastAPI leverages Python's async event loop (via Starlette/AnyIO) to handle high-concurrency non-blocking I/O without spawning thread overhead. |
| **2** | **B** | FastAPI automatically maps Pydantic schema validation failures into standardized RFC 7807 422 Unprocessable Entity responses with detailed field errors. |
| **3** | **B** | GET requests are read-only and idempotent; POST requests introduce server state modifications and are not idempotent by default. |
| **4** | **B** | High OFFSET values degrade performance because the engine must read and discard preceding rows; cursor pagination uses index seeks (`WHERE id > cursor`). |
| **5** | **B** | `Depends` enables clean inversion of control, managing the lifecycle of database sessions, settings, and authorization across endpoint handlers. |
| **6** | **A** | FastAPI inspects type hints and Pydantic models to auto-generate standard OpenAPI JSON schemas and interactive Swagger UI documentation. |
| **7** | **B** | Synchronous long-running operations block HTTP connections, causing proxy timeouts; HTTP 202 Accepted with async background workers is best practice. |
| **8** | **B** | Rate limiting protects database backends from query exhaustion, noisy neighbors, and denial-of-service attempts by metering requests per client. |
| **9** | **B** | Separate response schemas prevent accidental data leakage (PII, system credentials, internal hashes) by explicitly declaring public API contracts. |
| **10** | **B** | Production test suites must test both successful operations and defensive error boundaries (e.g. missing records, malformed IDs, invalid types). |
